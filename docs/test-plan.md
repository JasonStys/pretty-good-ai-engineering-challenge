## Failure-oriented coverage

The tests cover invalid account IDs and E.164 numbers, attempted destination changes, missing or
duplicate scenarios, malformed YAML types, absent synthetic-data classification, unexpected health
payloads, unavailable service, non-terminal calls, failed call status, recording timeout, missing
transcripts, malformed WebSocket JSON, oversize frames, invalid base64, missing handshake context,
forged Twilio signatures, bridge exceptions, secret patterns, incomplete conversations, and
cross-call inconsistencies.

## Live-call acceptance criteria

Each of the minimum ten calls must satisfy all of the following:

1. Uses the same reviewed Twilio caller number and only `+18054398008`.
2. Runs for approximately 1–3 minutes and ends naturally without a crash or runaway loop.
3. Produces a playable MP3 containing both sides and a role-labelled transcript with at least four
   turns.
4. Demonstrates coherent patient behavior, active steering, interruption recovery, and an appropriate
   ending.
5. Produces a structured QA report with quote-level evidence for each finding.
6. Contains no real patient data, credential, or unrelated caller information.

After a one-call smoke test, listen to the complete recording before running the sequential batch.
After the batch, listen to every recording, correct diarization if needed without changing spoken
content, run `pgai-voicebot validate --minimum-calls 10`, and compare issue evidence to audio.

  strongest call result.
- Separate AI-debug video shows a real failure and evidence-driven fix; it is not fabricated.
- No secret, `.env`, real DOB, personal medical information, or unrelated phone number is committed.
